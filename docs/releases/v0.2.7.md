# ArkBridge v0.2.7

Repeated health probes previously deleted and recreated the same source-scoped
policy rules. Tailscale reports each deletion through its diagnostic stream,
producing continuous `daemon.err` entries even while the primary route remains
healthy. Probe setup now keeps an exact existing rule in place, restores it if
it is missing, and updates ownership records without accumulating duplicates.

Rule checks use the live kernel state. A broader source prefix is ambiguous
only when it covers the probe's source address; unrelated prefixes coexist
without blocking the probe. Ambiguous rules and rules with additional selectors
are left untouched and make the probe invalid. Stale rules are removed only after the kernel confirms the exact plain tuple, so an
omitted selector such as `fwmark` cannot cause deletion of another service's
rule. Legacy destination-only probe rules are migrated only when that rule is
unambiguous. IPv6 address spellings are compared by the kernel's canonical rule
identity.

Probe routes are still reconciled on each check. Missing rules, rule-query
errors, IPv4 proxy-bypass failures, and the existing transactional route
rollback behavior retain their prior fail-closed semantics. The controller,
failover thresholds, default routes, DNS, firewall and USB companion are
unchanged.

Validation covers the full existing suite plus regressions for steady-state
rule retention, missing-rule recovery, lost ownership, source/priority changes,
legacy migration, ambiguous and marked rules, query failures, IPv6 canonical
forms, and bypass rollback. Linux kernel integration tests run in an isolated
network namespace. This fix does not claim physical failover, cold-boot, or
long-duration compatibility testing across all supported firmware.

If probe-rule teardown cannot verify ownership or the rule query fails, cleanup
returns failure and keeps ownership records. This does not add a background
probe-cleanup retry; an operator should resolve the conflict and rerun cleanup.
