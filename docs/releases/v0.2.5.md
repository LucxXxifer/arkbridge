# ArkBridge v0.2.5

Auto-check could select a link-local-only interface as the backup, and the
legacy panel could overwrite manual settings with the first candidate or a
guessed gateway. Detection now requires a global address, excludes bridge
members, and reads netifd's L3 device. Both panels fill confirmed device/gateway
pairs and select a backup only when it is unique for that address family.

When a primary device remains present but loses its IPv4 address, a confirmed
empty query now counts toward the normal failure threshold. Query failures,
malformed responses and addresses that reappear between queries continue to
hold state. Backup health, route/rule error handling and rollback checks remain
in force.

The engine can report a source/build version on APK systems through
`/usr/share/arkbridge/version`, with the existing opkg lookup as a fallback.
The installation guide explains how raw source deployments must reload `rpcd`
and refresh the LuCI session to load the existing ACL; package installs already
use LuCI's standard post-install hook. No ACL permissions were expanded.

Validation covers complete detector/engine scripts and both complete panel
scripts with synthetic fixtures, including confirmed address loss, unknown
health, IPv4/IPv6 candidate ambiguity and manual-field preservation. This
release does not claim physical cable-removal, reboot-persistence or long-term
acceptance on every supported firmware.

Release assets use the existing OpenWrt 24.10.3 SDK matrix and IPK format. They
are not APK packages for ImmortalWrt 25.12. Build the package feed against the
target firmware when another package format is needed. The companion
`usb-uplink` implementation is unchanged.
